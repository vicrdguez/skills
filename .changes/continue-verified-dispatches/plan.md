# Continue Verified Dispatches Plan

## Approach
Extend existing stage-oriented Work Start and handoff operations, not the harnesses. Keep verification in the Workflow Engine and associate the minimum authoritative round facts with existing Work Item backend projections. Verify one completed round, then delegate to slice 1's same-lane selection/waiting path. The reference identifies historical evidence, not ownership or permission for exactly one invocation.

Blocked by `wait-for-claimable-work`: both lanes support immediate `next`, bare `--wait` = 15m, `--wait=<duration>` and `--wait <duration>`, and `--poll <duration>`/`--poll=<duration>` default 30s. Poll requires a positive duration, is validated even without wait, and alone introduces no waiting. Immediate empty selection returns `no_work`; waiting exhaustion returns `idle_timeout`. Reuse that slice's parser, validation, deadline/cancellation behavior, and outcomes after it merges. Do not introduce a second waiting implementation.

## Implementation decisions

### Public contract
- Use `skl implement next --after <opaque-reference>` and `skl watchdog next --after <opaque-reference>`. `--after` is only a continuation input to queue selection, incompatible with explicit-item selection/resume-only overrides. Existing plain `next` and single-item commands remain supported.
- Add `worker_command` and `continuation_command` to successful queue dispatch output. Preserve existing `status`, `item`, and `packet`. A successful continuation also reports its verified previous Work Item and stage outcome as `previous_handoff`, distinct from any newly selected item, so a supervisor can report progress without inferring historical state. Consumers execute the returned commands; they do not reconstruct references, inspect labels, or implement success predicates.
- Worker commands use existing `skl <lane> resume --item <id> --repo <absolute-root> --remote <resolved-name>`. The existing packet-building path supplies the stage instructions and fixed obligations. Retrieval need not reproduce identical temporary Result Directory paths or stale comments.
- Associate Work Start and existing semantic handoff with the active round internally as necessary. Explicit resume remains by item and does not create another round for the active Claim. Add no `--dispatch` flag or ownership token to startup, resume, submit, or Needs Human. Stale worker-command replay across arbitrary later rounds is outside the one-supervisor-per-lane contract. Missing historical proof never gains continuation by inference.
- Startup must work before the conventional worktree exists: use the existing repository containing the Git evidence, not an assumed not-yet-created worktree. Packet handoff commands still target the worker's conventional worktree. Quote every generated shell argument correctly, including spaces and apostrophes; include absolute repository paths and the selected remote rather than relying on current directory or `origin`.
- Between `next` and startup, target movement must not replace the original pinned Target Snapshot or reviewed head. Preserve existing resume guards: a changed watched Submission head requires `fix_required` with the Claim and original obligation retained, not a newly pinned head or a false packet claiming the old head is still current. Test actual startup execution with the first implementation worktree absent and with existing worktrees; ordinary worker Git preparation, not the CLI, creates a missing worktree before handoff.
- Both current start paths allocate a Result Directory, and resume can allocate another. Prevent a per-dispatch orphan when startup supersedes the next packet: minimally reuse its directory or locally remove its superseded directory only after verifying engine ownership, private non-symlink location, and marker-only contents. Preserve any directory with result/repair documents or unexpected contents. Apply this to both lanes through the existing packet lifecycle and successful handoff cleanup; no global scan, migration, daemon, or new authoritative store. Directory paths may change, but discarded marker-only allocations must not accumulate in the normal next -> startup -> handoff path.
- Continuation commands retain the same lane, repository, remote, and effective wait/poll options, with no elapsed deadline embedded. The caller may explicitly override wait/poll using the normal contract. Each invocation starts a fresh idle window after verification.
- `work_available` always means one claimed dispatch; `no_work` and `idle_timeout` retain slice 1 semantics, with idle timeout describing only this lane's inactivity. Deterministic recovery uses existing `fix_required` plus actionable `reason` and known identity. Bad syntax and forge failures remain nonzero errors. No worker-result or worker-exit flag is needed.

### Round evidence and ordering
- A round identity is unique for a new dispatch of an item in a lane, including repeated reviews of the same commit. Item identity, head, target state, a result-directory basename, or the latest completed transition alone is insufficient. Resume reuses the active identity rather than minting another.
- Bind the opaque reference to repository, lane, Work Item, and a durable round identity; bind any existing Submission and fixed start obligation in backend facts. The reference locates evidence, it is not evidence itself or a security capability. Validate format/version and match trusted backend facts; choose the smallest encoding supported by these requirements.
- Reuse existing trusted Work Item metadata/history and add only the dispatch-start or completed-handoff facts needed to distinguish rounds. Keep proof attributable to its round when later metadata arrives. Use existing comment transport and pagination; add no global dispatch map, private authoritative file, registry, or continuation-consumption markers.
- A new dispatch becomes returnable only after selection's Claim and round binding are durable and read back. A failure after acquiring the Claim preserves it and stops. Existing Claims with no trustworthy round binding need explicit recovery; never guess that an old round is active.
- Bind handoff to its round and record completion only after the existing stage's full publication and guarded Claim-release readback succeeded. Implementation accepts Awaiting Review or Needs Human; Watchdog accepts Ready for Merge, Rework, or Needs Human. Include fixed reviewed and final post-marker head facts where relevant. Needs Human without a Submission is valid only on its legitimate implementation path.
- Preserve completion proof before successful Result Document cleanup. A worker/cleanup error after proven durable handoff does not revoke historical completion. A partial operation, retained Claim belonging to that round, or failure before complete proof remains non-continuable; continuation does not run status reconciliation or retry submit on its behalf.
- Completion evidence records release of the dispatched round's Claim, not a permanent requirement that the Work Item be unclaimed. Later claims, states, heads, and metadata must not erase it or be mistaken for it. If advancement races the final proof read and the engine cannot establish ordering, halt for explicit recovery rather than inventing proof.
- Before any next-selection attempt or waiting, verify that reference's completed handoff. Continuation is mutating, non-idempotent selection: an ordinary invocation with a previously used completed reference can select according to current eligibility. There is no consumed state, successor mapping, cached response, or retry/replay framework.
- Callers follow a single-use convention and stop on a lost or ambiguous response to either `next` or `next --after`; never automatically repeat either call. Inspect retained Claims and explicitly resume the chosen item; missing identity may require manual inspection. Document this before invocation because a lost response cannot carry recovery guidance. Preserve existing bounded backend retries and exact ambiguous-write readback, not automatic CLI-call retries.
- Support at most one supervisor per lane per project under the existing best-effort Claim model. No new ownership or duplicate-dispatch guarantee is introduced. Independent opposite-lane activity is supported.

### Module shapes & seams

#### [MODIFIED] CLI and Workflow Engine
`cmd/skl/implement.go`, `cmd/skl/watchdog.go`, and the slice 1 waiting entrypoint expose the contract above. `workflow/implement.go` and `workflow/watchdog.go` retain ordering, eligibility, read-back Claims, and packet construction. `workflow/handoff.go` and `workflow/review.go` connect semantic completion to the active round. Extend outcome/fact command wiring only as needed; the harness stays outside this module.

Dependencies: existing Backend interfaces are the replaceable external seam; real Git is the repository dependency; waiting uses slice 1's established timing seam. Tests go through the CLI with `implementationMemory`, `proposalRepository`, and `prepareSlice` in the existing command tests. Execute returned command arguments through the CLI rather than merely asserting string fragments; use a different caller directory and non-default remote. In B1/B2 inspect only the returned packet directory paths to prove local reuse/cleanup and preservation of result/repair documents across both lanes' next -> startup -> handoff, including startup drift/refusal controls. No private helper, codec, or per-function tests.

#### [MODIFIED] GitHub Backend
`setup/implementation.go` already publishes trusted `skl.implement/v1` metadata and projects only the latest `ImplementationTransition`; `setup/watchdog.go` reconstructs review/bounce history but has no round completion receipt. Extend semantic backend observations/mutations enough to retain and resolve a requested round. The Engine owns allowable targets and continuation policy; the adapter owns JSON/comment representation, trust filtering, pagination, and exact ambiguous-write readback.

Existing `implementationComment` metadata deduplication compares the latest trusted comment, not arbitrary historical round facts. Preserve its current callers while ensuring a later unrelated comment cannot cause duplicate or forgotten round facts. Keep old persisted metadata readable for shipped single-item behavior; absence of new evidence refuses continuation rather than fabricating it. Test through exported adapter methods over `httptest`, rebuilding the adapter from persisted HTTP state. Feed those observations into CLI tests where needed; a fake Backend alone cannot prove durable round isolation.

ADR 0002 forbids a private authoritative database and requires observation before retry; existing handoff reconciliation remains separate from non-idempotent continuation selection. The broader backend-independence correction recorded there remains separate.

PR #19 is merged (2026-09-08). Preserve its Round 1 findings and Round 2 resolutions: W1 requires affirmative mergeability at every pending-pass recovery guard; W2 distinguishes human requeue from a genuine bounce; W3 uses otherwise-valid held-Claim/wrong-stage negative fixtures; W4 uses a valid claimed Submission with real retired Git history and a no-mutation assertion. Relevant existing tests include `TestStatusPendingPassRequiresMergeabilityAndRetainsRecovery`, `TestWatchdogHumanRequeuePreservesFirstFailureBounce`, and `TestWatchdogReportsNoEligibleWork`. Keep existing Pi queue fixture checks passing without moving harness logic in this slice. Never require current mergeability to re-prove a historically completed pass after later valid advancement; do require it while completing a pending pass.
