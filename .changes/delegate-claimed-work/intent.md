# Delegate Claimed Work

## Why

Independent testing and implementation subwork can benefit from delegation without splitting ownership of a Work Item or weakening verification. Guidance must permit that bounded choice where supported, rather than reserve helpers exclusively for Audit or require a separate test writer.

## What

Allow one accountable implementor to delegate non-conflicting testing and implementation subwork within its existing Claim. Deliver capability-appropriate guidance through the post-#44 Execution Skills, relevant continuations, and surviving single-item implement runner. The owner integrates results, verifies the final functional state, and owns submission.

## Scope

- Optional delegation using established execution capabilities, with serial owner execution when unavailable and bounded discovery only when capability is genuinely unknown.
- Cross-context contractual inputs, bounded write responsibilities, unchanged Work Item identity and authority, and owner accountability.
- Focused rendered-guidance, capability-variant, and installation verification at existing seams.
- Implementation after `verify-contract-conformance` and external prerequisites #48, #49, and #50 are Merged, using their landed code through ordinary Git preparation.

## Out of Scope

- Automatic queue selection, additional Claims, delegated final publication, new Workflow roles, schedulers, capability registries, or harness integrations.
- Restoring disabled Pi loops or their retired JSON passthrough contract.
- Mandatory helper counts, a separate test-writing agent, or a separate worktree for every helper.
- Redesigning testing or acceptance criteria, artifact production, or target-integration policy owned by sibling slices; changing published ledgers.
- Model evaluations, live agent experiments, benchmarks, or claims that instruction checks prove agent behavior.

## Definition of Done

- [x] Complete relevant Execution Skills and continuations distinguish supported, unsupported, and genuinely unknown delegation capability without using harness identity as evidence.
- [x] Delivered guidance permits bounded, non-conflicting implementation/testing delegation within one Claim and preserves contractual inputs, owner authority, integration, and final-state verification.
- [x] Optional delegation fallback does not weaken mandatory Audit mechanisms, the Full Gate, independent Watchdog Review, artifact integrity, or the human merge boundary.
- [x] The installed single-item implement runner permits this delegation without further queue selection or re-enabling disabled loops, and installation preserves user-owned content.
- [x] Existing project checks and focused rendering, capability, and installation checks cover the delivered guidance and affected interfaces, with results and limitations recorded without agent-behavior claims.

## Manual verification

None.
