# Keep forge publication a reconstructible latest view

Forge Publication presents the latest relevant authoritative local result, not a queue of intermediate presentations that must eventually be delivered. In the replacement exploration for Work Item #63 and closed, unmerged PR #78, the human confirmed that publication must not introduce durable publication reservations, publication leases, or publication-specific lock files. Bounded best-effort publication may leave temporarily stale public content; the architecture must not trade that acceptable limitation for a durable coordination protocol that can block later publication. This sharpens ADR0006's private-ledger authority and latest-view publication boundaries.

## Decision scope

The human confirmed the complete replacement Explore recap, including consequential behavior, architectural commitments, scope exclusions, and deliberately delegated choices. This is the approved design input for Propose to materialize replacement work for #63 / closed PR #78. No replacement Contract or Work Item has yet been materialized; this record does not rewrite previously frozen Contracts or claim the behavior is implemented.

- Local implementation and review remain independent of forge availability. Missing intermediate public presentations need not be replayed before publishing the latest result.
- Attempt best-effort publication after acceptance and each completed phase. Also provide an explicit operation to publish the current view, whether or not an earlier attempt failed. It selects current authoritative local records, not pending publications or an unfinished attempt.
- Reuse ordinary non-force Git source publication for the recorded branch/revision when needed. Implementation will normally publish source; an explicit publication can encounter source left unpublished during an outage spanning sequential phases. Do not add a separate catch-up protocol or last-published-source metadata, modify code, manufacture review evidence, or overwrite conflicting remote history. If source publication cannot proceed, report that limitation without changing the local outcome.
- Retain GitHub draft/ready as best-effort presentation: pre-approval work is draft; a locally approved result may be presented as ready when the observed PR head matches the recorded final revision. Do not knowingly present different code as approved. Concurrent movement can leave temporarily stale public content; do not introduce a rollback transaction or persistent repair protocol to eliminate that possibility.
- Apply these boundaries to normal acceptance/handoff publication as well as explicit current-view publication. Simplify inherited publication coordination as needed rather than placing a new operation over retained reservations. Publication does not change worker Claims, completed Review Count, or local outcomes, and does not own merge/closure observation.
- Do not add or preserve durable publication reservations, publication leases, or publication-specific lock files as the replacement's publication coordination mechanism. Short locks protecting ordinary local ledger mutations are distinct from these prohibited publication mechanisms.
- Publication is bounded and best-effort, with explicit uncertainty rather than a claim of atomicity between GitHub and the ledger. Temporary stale public content is acceptable. This does not authorize knowingly publishing stale content or making forge prose authoritative.
- Retain established forge associations in the existing attachment fields: repository and issue/PR number connect the Work Item to its actual external objects. These are observed identities, not reservations or a publication history.
- Do not persist a registry of temporary public-body paths, digests, or reuse/view metadata. Each publication receives current agent-authored prose, supplied directly or reauthored from private evidence. Reauthoring after interruption is acceptable; temporary files can quickly become stale and mix information from different results. This replaces the old Contract's automatic cross-invocation prose-reuse convenience.
- Beyond established forge associations, drop forge-publication-specific tracking metadata: pending-attempt notes, a separate latest-publication phase selector, last-published-source receipts, body registration/digests, inline-publication receipts, and in-flight coordination records. Derive the desired presentation from authoritative local results rather than maintaining a second publication model. Implementors may not reintroduce these mechanisms to strengthen delivery guarantees or optimize reuse. This does not remove ordinary Work Item state, worker Claims, Phase Reports, their source/input references, or Git history.
- Publication is local-first and bounded: commit the local result before attempting publication, and allow the command to wait for the HTTP response or timeout. Forge failure cannot undo or invalidate local completion. No background publisher or queue is introduced. Replication/delivery terminology used during Explore was an analogy, not a requirement for a formal delivery guarantee.
- Accept that duplicate external creation is not guaranteed impossible across publication attempts when an earlier response was lost. Favor minimal machinery over a global at-most-once or exactly-once guarantee. Permit bounded immediate retries for reads and safely repeatable updates, stopping updates when the selected local result is superseded. Do not automatically retry a create whose effect is uncertain after a timeout or lost response; report the uncertainty and finish. Exhausting retries creates no durable recovery obligation or attempt record. A later explicit invocation uses the then-current local result rather than resuming an old attempt.
- Keep forge execution inside `skl`; do not delegate direct `gh` publication commands to agents in this replacement. Agents author human-facing prose and own judgment. The CLI uses established attachments, performs bounded transport, records successfully established attachments, and reports immediate outcomes without a durable delivery-coordination protocol.
- Exclude GitHub inline-finding publication from the replacement scope for now. Detailed findings are primarily agent-to-agent evidence carried in private Phase Reports, not material that must be synchronized to GitHub.
- Preserve optional human access to findings between review rounds. The human must be able to inspect the reasoning, identify workflow or architectural gaps, and decide whether intervention is warranted without becoming a mandatory review participant before Ready for Merge. Access is on-demand, with discoverability through ordinary status rather than a new notification system. This requirement does not authorize a new finding store or public review export. Expose the existing Git-backed evidence through `skl`: current report files at committed HEAD, exact historical versions, and their path-scoped history or recorded input references. Reports contain findings and their authored dispositions; no report registry or history index is needed. Filling the CLI access gap is ordinary interface work over existing storage, not a new subsystem. Defer an agent-guided viewer of the implementation/review cycle to a separate future feature; it is outside this replacement slice and must not become a new mandatory review gate. Access to recorded evidence does not promise reconstruction of undocumented agent decisions.

## Scope, delegated choices, and verification

The replacement covers latest-view issue/parent/PR presentation, the required simplification of normal publication paths, and access to existing private reports. Inline-finding publication, an agent-guided decision viewer, a notification system, background publication, a queue, durable recovery coordination, Human Decision intake, and merge/closure observation are outside its scope. Investigation and repair of the workflow-design failure tracked in #80 remain independent.

Command spelling, internal helper structure, and bounded retry parameters are delegated to implementation within these boundaries. New persistence, coordination mechanisms, responsibility transfers, or stronger delivery guarantees are consequential changes requiring renewed agreement, not implementation discretion.

Use existing Go verification tools and controlled Git/HTTP seams to establish the agreed behavior and failure modes, including interrupted publication followed by newer local work, preservation of local outcomes, bounded retries and uncertain creates, safe source publication, temporary stale presentation, and private report retrieval. Verify the absence of the prohibited durable publication machinery rather than merely renaming the old recovery protocol. ADR0005 continues to govern contract-grounded verification.

## Why this boundary is explicit

W3 in PR #78 demonstrated an interrupted implementation-publication reservation surviving a later local Watchdog handoff. Ordinary recovery refused the reservation, while explicit reconciliation refused because it referred to an older report. The human wanted the latest Watchdog result, not recovery of obsolete implementation prose. A protocol requiring the obsolete attempt to be resolved before newer presentation could proceed imposed an unintended architectural and operational burden.

The independent failure of contract/skill/review boundaries to identify architectural discretion is tracked in issue #80. Its diagnosis is separate from this replacement exploration.
