# Separate ledger browsing from workflow observation

The private Workflow Ledger replaced forge-hosted workflow visibility, but browsing it must not require forge access or change the work being inspected. The browser and read-only CLI output share a query module over locally committed ledger records; the TUI owns navigation and presentation, while the query module owns record reading, relationships, and consistent revision selection. Ledger storage paths are not the human navigation model: Projects contain Proposals and Slices, with lifecycle and Claim as independent dimensions.

Do not reuse the existing status command's completion observation as a browser refresh. That operation can contact the forge and write workflow state. Browser refresh instead reads one committed local ledger revision, with no fetch, reconciliation, or workflow mutation. The resulting view may lag external events such as a PR merge; that limitation is preferable to making inspection a network-dependent state transition. Explicitly opening an attached issue or PR in an external browser is separate from querying the ledger.

Read documents in their workflow context. A historical Phase Report has its own revision identity and does not rewind the surrounding Slice's current lifecycle, Claim, or Dependencies. Report Versions represent committed content changes, including metadata changes, rather than every ledger commit or inferred execution round; an archive move alone creates no new version. Discover versions from available local Git history across the active and archived locations, without a persistent history index. Preserve exact historical document references and disclose detectable limitations in available history.

Preserve access to recorded evidence even when its metadata cannot be interpreted, and disclose unreadable facts rather than substituting empty or healthy state. An unreadable record does not block unrelated browsing; affected summaries disclose incomplete information. Automatic and explicit refresh preserve navigation and keep an opened document stable while indicating when a newer version is available.

Introduce browsing independently of existing status reconciliation. The TUI entrypoint is `skl browse`; read-only CLI queries expose the same inventories, facts, documents, and report versions while preserving existing command behavior. Construct external GitHub links from recorded attachment identities rather than adding URL persistence or contacting the forge. Browser navigation state is session-local, not a new persisted ledger or configuration model.
